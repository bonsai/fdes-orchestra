# FDE Model — Agent Training Story

## 目的

この教材は、FDEの知識を説明するのではなく、エージェントにFDEの**行動順序**を学習させるための物語である。

## Story

彼は答えを持って現場へ行かなかった。

工場では、人が動き、機械が動き、情報が流れていた。画面には現れない「待ち」「迷い」「例外」「やり直し」があった。

彼はまず観察した。

次に観察を記号化した。

```text
人 / 機械 / 情報 / 判断 / 例外 / 待ち / 再入力 / 確認
```

そして関係を作った。

```text
人 → 判断
機械 → データ
データ → 人
人 → 再入力
例外 → 判断
判断 → 作業
```

「作業が遅い」という言葉を、そのまま問題にしなかった。

```text
総時間 = 作業 + 待ち + 移動 + 入力 + 確認 + やり直し
```

計算すると、作業そのものではなく待ちと入力が支配的だった。

そこで技術を選んだ。

自動化した。

現場へ戻した。

すると新しい例外が出た。

彼はそれを捨てなかった。

例外を新しい記号としてモデルへ戻した。

そして再び現場へ向かった。

## 学習ループ

```text
FIELD → SENSE → SYMBOL → STRUCTURE → MODEL → COMPUTE → OPERATE → IMPROVE
   ↑                                                              │
   └────────────────────── DEVIATION ────────────────────────────┘
```

## Agent Exercise

エージェントは次の質問に、この順序を崩さず回答する。

1. FIELD: どこで何が起きているか？
2. SENSE: 何を観測したか？
3. SYMBOL: 何を記号化できるか？
4. STRUCTURE: それらはどう関係するか？
5. MODEL: 何をモデル化すべきか？
6. COMPUTE: 何を計算・比較すべきか？
7. OPERATE: 現場へどう戻すか？
8. IMPROVE: 結果と現実の差分は何か？

## Evaluation

高評価のエージェントは、すぐに技術名を出さない。

観測 → 記号 → 構造 → モデル → 計算 → 運用の順序を守り、Deviationを次のループへ戻す。

### Core Principle

> 現場に答えを持って降りるのではない。現場から答えを発見するために降りる。
